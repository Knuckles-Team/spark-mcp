# spark-mcp development

Use this skill when changing the `spark-mcp` connector, its documentation, or
its spec-delivery integration. Read `AGENTS.md`, the affected module, and the
owning `specs/` row before editing. Keep Spark facts, records, and ontology
ownership in their existing connector and engine boundaries.

## Rapid delivery: the 5-minute contract

For a small, reviewable change:

1. Identify one requirement or maintenance slice and name the exact files it touches.
2. Reuse the existing Spark Connect client, SDK, central pipelines, and package
   conventions. Do not add another Spark transport, MCP server, planner, or CI
   framework.
3. Keep spec status generated by the canonical pipeline tools. Run the narrowest
   relevant tests, then run `pre-commit run --all-files` from the repository root.
4. Review the complete diff, including workflow and package-data changes, and record
   the source revision plus the commands and results used as evidence.
5. Keep credentials, endpoints, customer data, generated output, caches, and scratch
   files outside the checkout. A Pages claim is complete only after the reusable
   workflow has run and the exact published `spec-delivery/` source is checked.

### Change boundaries

- Preserve the existing Spark Connect runtime, MCP tools, A2A surface, transform
  safety gates, and ontology files; central release tooling owns generated connector
  artifacts.
- Extend an existing spec or connector operation before adding a new abstraction.
- Use the central Pages workflow and `.config/spec-dashboard.json` for the spec
  dashboard; keep one documentation publisher for this repository.
- Keep the central aggregate hooks in `.pre-commit-config.yaml`; do not copy their
  implementation or create a second CI framework.

### Validation evidence

For code changes, run the narrowest relevant mocked test first and then the repository
hooks. For delivery changes, validate JSON and YAML syntax and inspect the rendered
dashboard inputs before requesting review. Report failures with the command, revision,
and file or line that needs attention; do not hide a failing check behind a skipped
hook.
